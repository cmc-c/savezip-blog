# report_content.json 스키마

LLM이 생성해야 하는 보고서 콘텐츠 구조. 값은 모두 예시 형식 설명입니다.
실제 파일은 멘티 개인정보를 포함하므로 커밋 금지.

```jsonc
{
  "meta": {
    "student_name": "이름",
    "company": "회사명",
    "job": "직무명 (팀·세부직무 포함 가능)",
    "report_date": "YYYY년 M월",
    "filename": "{회사명}_{이름}님_면접준비보고서.docx"
  },

  // [라벨, 값] 배열 — 신입/경력, 회사, 직무, 근무지, 학력, 경력, 어학, 수상 등
  "basic_info": [["구분", "신입 (졸업예정)"], ["지원 회사", "..."]],

  "step0": {
    "title": "STEP 0. 기업과 직무 이해",
    // 세스코 예시 수준의 내러티브 문단들. 비문학 논문톤 유지.
    // 순서: 공고 해석 → 사업모델(BM) → 최근 사업 방향과 채용 배경
    //       → JD 업무 해석(축별) → 역량 매핑 앞문장 → 평가 관점 마무리
    // "연결하면 다음과 같습니다."로 끝나는 문단 뒤에 capability_map bullet이 삽입됨
    "paragraphs": ["..."],
    // "JD 요구 → 지원자의 근거" 매핑 bullet
    "capability_map": ["패키징 공정 이해 → 자소서에서 공정 용어 정확히 사용"]
  },

  "step1": {
    // O/△/X 매칭 표. matchCol(마지막 열)은 "O" | "△" | "X"
    "jd_matching": { "columns": ["JD 요구역량", "자소서/이력서 근거", "매칭"], "rows": [["...", "...", "O"]] },
    // 자소서 보완 포인트 섹션은 사용하지 않음 (보고서에서 제외)
    "cross_check": { "columns": ["체크 포인트", "준비 방향"], "rows": [] }
  },

  "step2": {
    "intro": "안내 문장",
    // 정확히 5개. answer는 40초 분량 두괄식, 본인이 채울 부분은 [대괄호]
    "strengths": [{ "title": "강점 1. ...", "evidence": "...", "answer": "...", "usage": "..." }]
  },

  "step3": {
    "intro": "안내 문장",
    // 정확히 5개. tip은 난이도 낮게 ("~해 두세요", "~만 알아두면 충분합니다")
    "items": [{ "title": "보강 1. ...", "question": "...", "direction": "...", "answer": "...", "tip": "..." }]
  },

  "step4": {
    "checklist": { "columns": ["No.", "항목", "이렇게 준비하세요"], "rows": [["1", "...", "..."]] },
    "concepts": { "columns": ["No.", "개념", "이 정도만 알아두세요"], "rows": [["1", "...", "..."]] }
  },

  // 권리 안내 2줄 (고정 문구)
  "footer": [
    "본 보고서의 저작권은 자인스쿨에 있으며, 무단 복제 및 배포를 금합니다.",
    "본 보고서는 수강생 개인의 면접 준비 목적으로만 사용 가능하며, 외부 공유를 금합니다."
  ]
}
```

## 톤앤매너 (콘텐츠 생성 시 필수)

- 금지: "취약점/약점", "부족/부재", "불일치/괴리/공백", "논리적 비약/과장", "공격/방어", "면접관"
- 대체: "보강 포인트", "보강 필요", "체크 포인트", "경험 연결 강화 필요", "예상 질문/답변 방향", "평가자"
- X 매칭도 긍정 톤: "아직 경험이 없는 영역 → 입사 후 학습"

## 자인스쿨 금칙어 (모든 텍스트에 적용)

- 가운뎃점(·) 사용 금지 → 쉼표 또는 "와/과"로 대체
- 금지 단어(파생형 포함): 구조, 설계, 전환, 실질, 실제, 실행, 단순, 체계, 실무, 흐름, 맥락, 감각, 정렬, 병목, 실체
- "재~" 복합어(재측정, 재구성, 재편 등) 금지 → "다시 ~" 형태로 풀어쓰기
- "~가 아니라", "~가 아닙니다" 형태의 꾸밈용 부정 구문 금지 → 긍정 서술로 직접 기술
- 비유 표현(그림이 보인다, 감을 잡다 등) 금지, 비문학 논문톤 유지
- 지시어 접속 표현(이처럼, 이를 통해 등)은 한 문단 1~2회 이내

## STEP 0 사실 검증 규칙 (필수)

기업조사 내용은 아래 기준으로 검증한 뒤에만 보고서에 쓴다.

1. **확인된 사실만 단정형으로 쓴다.** 출처(공식 사이트, 공시, 언론 기사)에서 직접 확인한 내용만
   "~입니다"로 기술한다. 회사의 법적 성격(법인, 지주회사, 그룹 브랜드명)을 혼동하지 않는다.
2. **추정은 추정으로 표시한다.** 출처 기반 해석은 "~로 해석할 수 있습니다", "~할 가능성이 높습니다"로만 쓴다.
   기사 제목이나 단편 정보에서 직무의 담당 범위, 조직 구성 같은 세부 사실로 확장하지 않는다.
3. **공고에 없는 정보는 역질문으로 전환한다.** 소속 법인, 담당 범위, 팀 구성처럼 공고와 조사로
   확인되지 않는 정보는 단정하는 대신 "면접에서 확인할 질문"으로 멘티에게 안내한다.
4. **조사 출처를 기록한다.** 콘텐츠 생성 시 참고한 출처 URL 목록을 별도로 남긴다 (보고서 미노출,
   운영자 검토용 — Discord 알림에 함께 전달 가능).

## 질문 리스트 (모드 B, docx 미포함)

- 20개, 번호만, 순수 질문 문장만
- 기본질문(자기소개/지원동기/포부/장단점 등) 및 지정 블랙리스트와 의미 유사 질문 금지
- 모든 질문은 자소서/이력서/JD/기업조사 근거 기반
